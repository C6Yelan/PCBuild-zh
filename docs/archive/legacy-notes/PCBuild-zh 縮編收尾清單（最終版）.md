# PCBuild-zh 縮編收尾清單（最終版）

## 1. 這份文件的目的
本專案不再追求持續擴大功能，而是以「完成一個可交付、可維護、可回顧的第一階段版本」為目標。

本次收尾只保留真正有價值且能在合理時間內完成的內容，避免專案再次膨脹。

---

## 2. 本次收尾只做三件事

### 2.1 提高推薦品質
只處理會直接影響配單合理性與可信度的項目。

範圍：
- 相容性規則補強
- retrieval / context pack 品質改善
- 使用者需求正規化
- 降低過時、缺貨、明顯不合理零件被推薦的機率

完成標準：
- 明顯不相容配單下降
- 過時或不合理配單下降
- smoke / regression 對比結果能看出品質至少沒有退步

---

### 2.2 固定使用目前已接上的外部免費開源 AI
本階段不再擴充新的 provider，不再追求多模型比較，只保留目前已接好的外部免費開源 AI 作為主線。

範圍：
- 維持目前可用的 OpenAI-compatible 主線
- 確保 `.env` 可正常切換既有設定
- 保留最小必要 smoke test / regression test
- 確保 request_id、provider、model、context_pack_hash 等追溯資訊仍可用

完成標準：
- 現有 provider 可穩定回覆
- 基本 smoke 可跑通
- regression 可用來檢查本次修改沒有明顯破壞主線

---

### 2.3 補齊必要說明文件
本次只補最小必要文件，不做大規模文件工程。

範圍：
- 說明目前專案已完成到哪裡
- 說明目前正式支援的 AI 使用方式
- 說明如何切換 `.env`
- 說明如何執行最小必要測試
- 說明哪些內容已明確列為暫不處理

完成標準：
- 我未來隔一段時間回來看，仍能快速知道怎麼啟動、怎麼測試、目前做到哪裡
- 不需要重新讀大量舊文件才能理解現況

---

## 3. 本次明確不做的事情
以下內容直接列為「本階段不做」：

- 不重做 Grafana / Loki / dashboard
- 不再擴充新的 AI provider
- 不做 Gemini、本地模型、多平台比較
- 不做前端新功能
- 不做聊天紀錄 / 歷史紀錄功能
- 不追求全面重構整個 backend
- 不處理 T6 官網核對與自動修補
- 不為了整理而持續拆小檔案到無上限

原則：
只要某件事沒有直接提升「配單品質」、「現有 AI 主線穩定度」或「未來可維護性」，就不做。

---

## 4. 建議實作順序

### 第 0 步：先凍結目前版本
- 先確認目前可用版本可回退
- 保存目前 `.env` 對應的 provider / model 設定
- 保存目前 smoke / regression / release check 指令
- 先 commit / push 一次，作為收尾前基線

### 第 1 步：做推薦品質改善
優先順序：
1. 相容性規則
2. retrieval / context pack 改善
3. 使用者需求正規化
4. guardrails 微調

### 第 2 步：穩定既有 AI 主線與最小測試
- 確認目前外部免費開源 AI 可穩定使用
- 確認 `.env` 切換與 provider 設定正常
- 補齊或整理最小必要 smoke / regression

### 第 3 步：補文件
- 補 README 或 docs 中最必要的操作說明
- 補目前範圍與不做項目
- 補收尾版狀態說明

### 第 4 步：收尾
- 最後檢查一次主要流程
- commit / push
- 將此專案定義為「第一階段完成版」或「維護前基線版」

---

## 5. 本次收尾的驗收條件
只要以下成立，就可以視為本次收尾完成：

- 推薦品質比目前基線更合理，且沒有明顯退步
- 現有外部免費開源 AI 主線可正常使用
- smoke / regression 可執行並能作為基本驗收依據
- 文件足夠讓未來的我快速接手
- 已明確寫出本階段不做的事情
- 專案可以正式進入維護狀態，而不是繼續膨脹

---

## 6. 最終定位
這個專案本階段的最終定位不是「做滿所有想法」，而是：

**完成一個可用的中文 AI 配單 MVP，並把它收斂成可維護、可回顧、可延續的第一階段成果。**
